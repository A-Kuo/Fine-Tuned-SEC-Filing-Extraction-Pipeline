Item 1 Business

Every SEC filing has two kinds of numbers.

Some are machine-tagged in iXBRL — deterministic, already structured. The rest live in prose: MD&A, footnotes, non-GAAP reconciliations. This pipeline reads the part XBRL doesn't cover, using a QLoRA fine-tuned Llama 3.1 8B, and never lets an inference overwrite a tagged fact.

Item 7 Architecture & Analysis

Xbrl wins. Always.

Extraction runs in two tracks that write to the same schema. The xbrl track parses filer-tagged facts — deterministic, confidence 1.0, no model involved. The llm track covers everything left over: narrative sections a tag was never attached to. Both tracks emit the same record shape, tagged with the method and confidence that produced it, so a downstream reader can tell which numbers to trust unconditionally and which to verify.

01 · deterministic

iXBRL parse

Filer-tagged facts read directly from inline XBRL. No inference — a number the company itself machine-tagged.

02 · segmentation

Section extraction

Untagged prose is split into MD&A, risk factors, and financial-statement sections before anything is inferred.

03 · inference

QLoRA extraction

Llama 3.1 8B, NF4 4-bit + LoRA (r=16), reads each section and emits structured JSON with a confidence score.

04 · recovery

5-stage parser

Fence-stripping, brace-matching, truncation repair, and field-level regex fallback recover a result from imperfect model output.

Enforced at the database layer, not just in application code: WHERE NOT (method = 'xbrl' AND EXCLUDED.method != 'xbrl') — an llm fact can never overwrite an xbrl fact for the same key. The reverse is permitted.

Item 2 Properties

The stack

Three services, each doing exactly one job — no service holds a responsibility another one already owns.

Postgres · Supabase

System of record

Two schemas: a flat live-serving table set, and a normalized intel.* schema with lineage, RLS, and pgvector for retrieval.

GPU · Kaggle / SageMaker

Inference

Training runs on Kaggle's free T4; serving is scaffolded for SageMaker Async Inference — GPU on demand, scaled to zero when idle.

FastAPI · Vercel

Interface

A model-serving API plus a static debug console — kept as separate deployables, since one needs a GPU and the other emphatically doesn't.

Item 1A Risk Factors

Where this is still honest about being unfinished

—

No trained adapter yet

Every real benchmark above ran on base weights. The training workflow is fixed and ready; it hasn't been run for a final adapter.

—

The heuristic track doesn't generalize

Measured directly against 5 real 10-Ks: 0 of 5 produced a usable number. It works on short synthetic text and nothing else, by design of what it's for.

—

Accuracy figures are targets, not results

92–99% field accuracy is an unverified goal carried from the project spec, clearly separated in the evidence table above from anything actually measured.
